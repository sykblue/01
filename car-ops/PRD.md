# PRD · 공용차 배차판

> 작성일 11/17 · 상태: v1 (초안)
> 이 문서는 **무엇을 만들지 정하는 기준**이에요. 완료 기준은 **눈으로 확인할 수 있는 문장**으로 써요.
> "빠르게 보인다" ❌ → "다른 사람 화면에 3초 안에 '사용 중'이 보인다" ✅

**한 줄 소개**: 회사 공용차 20대를 누가 쓰고 있는지 한 화면에서 보고, 버튼 하나로 빌리고 반납하는 웹페이지
**만드는 방법**: 한 페이지 웹(HTML + JavaScript) + Supabase(데이터베이스) · Vercel로 배포

---

## 1. 문제 (누구의 어떤 문제인가)
- **주인공**: 공용차 20대를 함께 쓰는 직원 12명 (영업 · 마케팅 · 개발 · 경영지원 · 고객지원)
- **지금 방식**: `carlist.xlsx` 한 파일에 차량목록과 배차기록을 손으로 적는다
- **문제**
  1. 여러 명이 동시에 열고 고칠 수 없다. 누가 파일을 열고 있으면 나는 못 적는다
  2. 적는 사람마다 형식이 달라서 기록이 뒤죽박죽이 된다 (아래 "지금 엑셀의 이상한 값" 참고)
  3. 차량목록의 `상태`와 배차기록이 따로 놀아서, **실제로 사용 중인데 '대기'로 보이는 차**가 생긴다
  4. 반납할 때 주행거리를 깜빡하거나 잘못 적어도 아무도 모른다
- **언제 여나**: 차를 빌리러 가기 직전(빈 차 찾기) · 차를 세우고 돌아와서(반납)

### 지금 데이터 (`carlist.xlsx`)
| 시트 | 줄 수 | 칸 |
|---|---|---|
| 차량목록 | 20대 | 차량번호 · 차종 · 연료 · 연식 · 현재주행거리(km) · 보관위치 · 상태 · 메모 |
| 배차기록 | 99건 | 번호 · 차량번호 · 사용자 · 부서 · 출차일시 · 반납일시 · 출차km · 반납km · 목적지 · 용도 · 비고 |
| 직원 | 12명 | 이름 · 부서 · 연락처 · 이메일 |

- 지금 상태: 대기 15 · 사용중 3 · 정비중 2 (그런데 배차기록상 반납 안 된 차는 **4대**, 1대가 어긋남)

### 지금 엑셀의 이상한 값 (옮기기 전에 고칠 것)
| 위치 | 문제 | 고치는 방법 |
|---|---|---|
| 배차기록 5 · 10 · 17행 | 날짜 형식이 다름 (`2026.10.27 14:50` · `10/29 11시` · `10월 30일 오전 9시`) | 모두 `2026-10-29 11:00` 모양으로 |
| 배차기록 22행 (번호 21) | 반납했는데 반납km 빈칸 | 다음 출차km를 반납km로 채움 |
| 배차기록 29행 (번호 28) | 반납km 5,497 < 출차km 54,934 (숫자 하나 빠짐) | 다음 출차km로 바로잡음 |
| 배차기록 35행 | 차량번호 띄어쓰기 없음 (`102고2981`) | `102고 2981` |
| 배차기록 42행 | 사용자 빈칸 | 부서에 물어 채우거나 `미상` |
| 배차기록 47행 | 출차km에 글자 (`22,475km`) | 숫자만 `22475` |
| 차량목록 13행 | 연식 빈칸 | 차량 등록증 보고 채움 |
| 차량목록 `192오 9043` | 사용 중인데 상태 '대기' | 새 시스템에서는 상태를 **적지 않고 계산**함 (규칙 R3) |

## 2. 기능과 완료 기준 (위에서부터 만든다)
| # | 기능 | 완료 기준 (이것만 보고 검수한다) | 상태 |
|---|---|---|---|
| F1 | 차량 목록 | 20대가 카드로 보인다. 카드마다 차량번호 · 차종 · 연료 · 보관위치 · 현재주행거리 · 상태(🟢 대기 / 🔴 사용 중 / ⚪ 정비중)가 보인다. 맨 위에 "대기 14 · 사용 중 4 · 정비중 2"처럼 상태별 대수가 보이고, 합은 항상 20이다. "대기만 보기"를 누르면 대기 차만 보인다. 차가 0대면 "등록된 차가 없어요"가 보인다. | ⬜ |
| F2 | 배차 현황 (지금 누가 쓰나) | 사용 중인 차마다 차량번호 · 사용자 · 부서 · 출차 시각 · 목적지 · "2시간 10분째"가 보인다. 출차가 오래된 순으로 보인다. 사용 중인 차가 0대면 "지금 나가 있는 차가 없어요"가 보인다. | ⬜ |
| F3 | 빌리기 (출차) | 대기 차 카드에서 [빌리기]를 누르면 사용자(직원 12명 중 선택) · 목적지 · 용도를 넣는 칸이 열린다. 출차 시각과 출차km는 자동으로 채워진다(지금 시각 · 차의 현재주행거리). [확인]을 누르면 그 차가 🔴 사용 중으로 바뀌고 F2 목록 맨 아래에 나타난다. 사용자나 목적지가 비어 있으면 "사용자와 목적지를 적어 주세요"가 보이고 저장하지 않는다. | ⬜ |
| F4 | 반납하기 | 사용 중인 차에서 [반납]을 누르면 반납km 칸이 열린다. 반납km를 넣고 [확인]을 누르면 반납 시각이 자동으로 적히고, 차가 🟢 대기로 바뀌며, 차의 현재주행거리가 반납km로 바뀐다. 화면에 "이번 운행 125km"처럼 달린 거리가 보인다. 반납km가 비었거나 출차km보다 작으면 이유를 알려 주고 저장하지 않는다 (규칙 R4). | ⬜ |
| F5 | 바로 반영 (실시간) | 화면 두 개(내 PC · 동료 PC)를 열어 두고 내 화면에서 빌리면, **새로고침 없이 3초 안에** 동료 화면에서도 그 차가 🔴 사용 중으로 바뀐다. 반납도 똑같이 3초 안에 🟢 대기로 바뀐다. | ⬜ |
| F6 | 내 운행 기록 보기 | 사용자를 고르면 그 사람의 최근 운행 10건(날짜 · 차량번호 · 목적지 · 달린 거리)이 최신 순으로 보인다. 기록이 0건이면 "아직 운행 기록이 없어요"가 보인다. | ⬜ |

완료 기준 체크
- [x] 숫자가 있다 (20대, 3초, 10건, 몇 km)
- [x] 잘못 입력했을 때 무슨 일이 생기는지 있다
- [x] 결과가 없을 때(0대 · 0건) 무엇이 보이는지 있다

## 4. 규칙
| # | 규칙 | 왜 |
|---|---|---|
| **R1** | **이미 사용 중인 차는 빌릴 수 없다.** 사용 중인 차에는 [빌리기] 버튼이 없다. 두 사람이 같은 차를 거의 동시에 눌러도 **먼저 저장된 한 명만 성공**하고, 다른 한 명에게는 "방금 다른 분이 빌렸어요"가 보인다. | 같은 차를 두 명이 빌리는 일을 막으려고 |
| **R2** | **반납하면 다시 빌릴 수 있다.** 반납이 저장되는 순간 그 차는 🟢 대기가 되고 [빌리기] 버튼이 다시 나타난다. | 반납 후 바로 다음 사람이 쓸 수 있게 |
| **R3** | 차의 상태는 **사람이 적지 않고 계산한다.** 반납 안 된 운행 기록이 있으면 '사용 중', 정비 표시가 있으면 '정비중', 아니면 '대기'. | 지금 엑셀처럼 상태와 기록이 어긋나지 않게 |
| **R4** | **반납할 때 주행거리(반납km)는 꼭 넣는다.** 숫자만 받고, 출차km 이상이어야 한다. 한 번 운행에 1,000km를 넘으면 "1,000km가 넘어요. 맞나요?"로 한 번 더 확인한다. | 깜빡하거나 숫자를 빠뜨리는 실수를 막으려고 |
| R5 | 정비중인 차는 빌릴 수 없다. | 고장 난 차를 내보내지 않게 |
| R6 | 반납은 아무나 할 수 있다 (빌린 사람이 아니어도). 대신 기록에 반납한 사람 이름이 남는다. | 동료가 대신 차를 세우는 일이 흔해서 |
| R7 | 날짜는 모두 `2026-11-17 15:00` 모양, 주행거리는 쉼표 없는 정수로 저장한다. 화면에서만 `53,020 km`처럼 보여 준다. | 형식이 섞이지 않게 |
| R8 | 운행 기록은 지우거나 고치지 않는다. 새 줄을 더하기만 한다. | 누가 언제 썼는지 기록을 지키려고 |

## 5. 하지 않을 것 (이번 버전)
- **관리자 화면**: 차 추가 · 삭제, 직원 관리, 권한 설정 화면은 만들지 않는다. 차나 직원이 바뀌면 Supabase 표에서 직접 고친다.
- **로그인**: 회원가입 · 비밀번호는 없다. 직원 12명 중 이름을 고르는 것으로 대신한다.
- **미리 예약**: "내일 오전에 쓸게요" 같은 예약은 없다. 지금 빌리고 지금 반납하는 것만 한다.
- **정비 관리 · 주유비 · 통계 대시보드 · 알림(문자 · 카톡)** 은 없다.
- **기록 수정 · 삭제**: 잘못 적은 기록은 고치지 않는다 (규칙 R8).

## 6. 기술
| 부분 | 쓰는 것 | 하는 일 |
|---|---|---|
| 화면 | `index.html` 한 장 + JavaScript | 목록 · 현황 · 빌리기 · 반납 |
| 데이터베이스 | **Supabase** (PostgreSQL) | 누가 열어도 같은 현황 |
| 실시간 | Supabase **Realtime** | 빌리기 · 반납이 생기면 모든 화면에 바로 알림 (F5) |
| 배포 | Vercel | GitHub에 올리면 자동 배포 |

### 표 3개 (Supabase)
```
cars      차량       plate(차량번호) · model · fuel · year · mileage_km · place · in_repair(정비중 여부) · memo
staff     직원       name · dept
trips     운행 기록   id · plate · user_name · dest · purpose · out_at · out_km · ret_at · ret_km · ret_by
```
- 차의 '사용 중'은 `trips`에서 `ret_at`이 비어 있는 줄로 계산한다 (R3)
- **같은 차에 반납 안 된 줄은 하나만** 있을 수 있게 데이터베이스가 막는다 (R1의 "먼저 저장된 한 명만 성공")
- `ret_km >= out_km`은 데이터베이스에서도 한 번 더 검사한다 (R4)
- 처음 데이터는 `carlist.xlsx`의 이상한 값을 고친 뒤 옮긴다 (차량 20 · 직원 12 · 운행 기록 99)

### 성공 기준
- 엑셀에서 옮긴 데이터로 화면을 열면 **20대 · 사용 중 4대**가 보이고, 배차기록상 사용 중인 `192오 9043`도 🔴 사용 중으로 보인다.
- 두 사람이 각자 휴대폰으로 같은 대기 차의 [빌리기]를 동시에 누르면, 한 명만 성공하고 둘의 화면 모두 3초 안에 같은 상태가 된다.

### 조심할 점 (초보 메모)
- 로그인이 없어서 **주소를 아는 사람은 누구나** 빌리기 · 반납을 누를 수 있다. 주소는 사내에만 공유한다.
- Supabase 키는 `anon` 공개 키만 화면에 넣는다. `service_role` 키는 절대 화면이나 GitHub에 넣지 않는다.
